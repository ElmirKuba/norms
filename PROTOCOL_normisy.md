## 8. ЧАТЫ И E2E ШИФРОВАНИЕ

**Модель чата:**
- Чат = соединение между двумя конкретными устройствами
- Каждый чат имеет название (тему)
- С одной парой устройств — безлимитное количество чатов
- ID чата: `uuid-v4_timestamp-13digits-ms`

**Ключи:**
- Каждый чат — своя асимметричная пара ключей
- Приватный ключ никогда не покидает устройство
- Публичный ключ передаётся через сервер, после обмена удаляется

**Шифрование:**
```
А пишет Б:
1. Шифрует сообщение публичным ключом Б
2. Отправляет по WSS (TLS)
3. Сервер доставляет зашифрованный blob
4. Сервер удаляет сообщение
5. Б расшифровывает приватным ключом
```

Два уровня: TLS (транспорт) + E2E (содержимое).

## 9. СОЗДАНИЕ ЧАТА И UX

**Флоу:**
1. Нажать "+" → выбрать контакт → выбрать его устройство → ввести название
2. Генерируется локальная пара ключей
3. Публичный ключ уходит на сервер, чат в статусе **"ожидает"**
4. Когда устройство собеседника онлайн — сервер обменивает ключи
5. Чат становится **активным**

**Оптимистичная отправка:** сразу после создания чата можно писать. Сообщения хранятся локально в `pending_key`, шифруются и отправляются автоматически когда придёт публичный ключ.

## 12. СЕРВЕР

**Транзитный — не хранилище.**

**Знает:** аккаунты, устройства (системные имена, refresh токены), публичные ключи временно, зашифрованные сообщения временно.

**Не знает:** содержимое сообщений, приватные ключи, псевдонимы устройств, историю переписки.

**Синхронизация:** клиент запрашивает "новее ID X" → сервер отдаёт и удаляет.

**Транспорт:**
```
HTTPS → авторизация, инвайты, обмен ключами, метаданные
WSS   → сообщения реалтайм, статусы онлайн, кик устройств
```

## 15. TODO (приоритетные)

### Миграция чатов
Перенос (не копирование) чата между своими устройствами:
- Новое устройство генерирует временную пару ключей
- Старое шифрует ею оригинальную пару ключей + историю
- Передаёт новому устройству
- Новое расшифровывает
- Сервер меняет только идентификатор устройства
- Собеседник ничего не замечает, его публичный ключ не меняется

### DPI-обход
По аналогии с GoodbyeDPI/Zapret/Zapret2:
- Маскировка TLS-фингерпринта на уровне приложения (как Telegram)
- Desktop: WinDivert (Windows), nfqueue (Linux)
- Android: VpnService API
- iOS: почти нереально без Apple entitlement

## 17. БЛОГ (TODO — отдельный проект)

**Общее:** веб-версия, доступна без приложения.

**Назначение:** гайды по приватности, безопасности, анонимности, обходу блокировок. Важно для прав человека.

### Категории
- Бесконечная вложенность
- Несколько категорий на статью
- Удаление категории: вместе со статьями или переместить в "без категории"
- Статья знает свою категорию, категория не знает о скрытых статьях

### Видимость статей

| Тип | Блок новых | В категории | Поиск | Категория на странице |
|---|---|---|---|---|
| Публичная | ✅ | ✅ | ✅ | ✅ |
| Публичная + пароль | ✅ | ✅ | ✅ | ✅ |
| По ссылке | ❌ | ❌ | ❌ | ✅ |
| По ссылке + пароль | ❌ | ❌ | ❌ | ✅ |

### Шифрование статей — E2E на фронте (Web Crypto API, AES-256)
```
Автор:
  → вводит пароль
  → фронт шифрует контент AES-256
  → фронт хеширует пароль (bcrypt/argon2)
  → сервер получает: зашифрованный blob + хеш пароля
  → сервер никогда не видит пароль

Читатель:
  → вводит пароль
  → фронт хеширует → отправляет хеш + ID статьи
  → сервер сравнивает хеши → отдаёт зашифрованный blob
  → фронт расшифровывает blob локально (миллисекунды)
  → сервер содержимое не видит
```

### Поиск
PostgreSQL FTS на старте → Meilisearch/Elasticsearch при росте.
