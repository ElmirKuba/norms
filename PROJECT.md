# Project: Нормисы

## What is this?
Кросс-платформенный E2E-шифрованный мессенджер. Одна Angular-кодовая база собирается под три платформы:
- **Мобилка** — iOS + Android через Capacitor
- **Десктоп** — Windows / macOS / Linux через Electron
- **Браузер** — лендинг + заглушка со ссылками на скачивание. Никакой функциональности приложения (регистрация, логин, мессенджер, настройки) в вебе нет — всё только в нативной приле.

## Goal
Кросс-платформенный E2E-шифрованный мессенджер для близкого круга. Без телефона и email при регистрации, с честной приватностью без компромиссов.

## Target Audience
Узкий круг «своих» — друзья, семья, доверенные сообщества. Закрытая регистрация по инвайтам — механизм отбора, а не маркетинговый трюк. Не для массового рынка.

Внутри этой аудитории — пользователи, ценящие приватность и анонимность, противники привязки к номеру/email, технически грамотные настолько, чтобы понять и принять компромиссы E2E (например, что recovery не возвращает чаты, что чаты живут на конкретном устройстве).

## Philosophy
Три принципа, в порядке приоритета:

1. **Приватность по умолчанию, без компромиссов и без бэкдоров.** Честно объясняем юзеру, что мы можем и не можем. Recovery не возвращает чаты — пишем это прямо в UI. Сервер не может прочитать сообщения — это свойство протокола, не обещание администрации.
2. **Простота через ограничения.** Один способ делать каждую вещь. Никаких опций «для удобства», которые ослабляют модель. Меньше развилок в UI = меньше способов наступить на собственную ногу.
3. **Прозрачность.** Всё, что сервер знает и не знает — задокументировано открыто и проверяемо. См. [`docs/server.md`](docs/server.md).

## Non-Goals
- **Веб-версия мессенджера** — в браузере только лендинг + заглушка.
- **Регистрация и логин в вебе** — аккаунт создаётся и используется только в нативной приле.
- **Блог в основной приле** — выделен в отдельный проект ("потом-потом").

## Non-Goals (MVP)
- **Медиа в чатах** — только текстовые сообщения. Без файлов, фото, видео, голосовых, стикеров.
- **`FilePickerService` / `CameraService`** — не реализуются до завершения базового текстового обмена.

## Repository Structure
Два независимых `package.json`: фронт (`application/`) и бэк (`backend/`). Без Nx/Turbo/workspaces. Внутри `application/` — один `ng build` → три платформы.

```
norms/
├── application/              ← Angular + Capacitor + Electron (свой package.json)
│   ├── package.json
│   ├── angular.json
│   ├── capacitor.config.ts
│   ├── src/                  ← Angular код (универсальный)
│   ├── dist/                 ← билд (общий для всех платформ)
│   ├── electron/
│   │   └── main.js           ← Electron entry
│   ├── ios/                  ← генерируется Capacitor
│   └── android/              ← генерируется Capacitor
├── backend/                  ← NestJS (свой package.json). См. docs/backend-stack.md
│   ├── package.json
│   ├── src/
│   ├── drizzle/              ← миграции
│   └── docker-compose.yml
├── docs/                     ← проектная документация
├── design/                   ← .pen файлы
├── nest-backend-example/     ← справочный бэкенд (удалить после)
├── CLAUDE.md
├── PROJECT.md
└── TODO.md
```
