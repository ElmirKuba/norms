# Устройства и чаты (мульти-девайс UX)

Чат привязан к **паре конкретных устройств** (см. [`encryption.md`](encryption.md)). Этот документ — про MVP-UX, который вытекает из такой модели: что видит юзер с двумя устройствами, что видит юзер на новом устройстве после потери старого.

## Принцип

**Один чат — одно устройство с каждой стороны.** Никакой автоматической синхронизации чатов между моими устройствами. Это следствие E2E-модели: приватные ключи никогда не покидают устройство, миграция требует временных ключей и онлайна обоих устройств.

Полноценная миграция — в потом-потом ([`TODO.md`](../TODO.md) → потом-потом → «Миграция чатов между своими устройствами»).

## Сценарий A: «У меня два устройства»

**Ответ:** ничего особенного не делаем. Чаты живут per-device, юзер сам решает.

- Иван написал мне с iPhone в чат «фильмы» — этот чат есть только на iPhone.
- Если хочу обсуждать с MacBook — Иван должен явно создать со мной чат с MacBook, выбрав мой MacBook из списка моих устройств в модалке создания чата.
- Альтернатива (мульти-таргет, авто-создание чатов на все мои устройства) — отвергнута: overhead на шифрование/хранение, прячет сложность модели от юзера.

## Сценарий B: «Новое устройство (recovery, переустановка, второе устройство)»

При первом успешном логине **новой сессии** (т.е. в `sessions` создалась новая запись для этого `account_id`) — фронт запрашивает у бэка список «осиротевших» собеседников.

### Что такое «осиротевший собеседник»
Аккаунт, с которым у меня были чаты с **других моих устройств** (других сессий этого же `account_id`), но **нет чатов с текущей сессии**.

Сервер знает это из таблицы `chats`: фильтр `session_a_id IN (мои_другие_сессии) OR session_b_id IN (мои_другие_сессии)` → собираем уникальные `peer_account_id`.

### Что показывает UI
Экран «Welcome» / баннер при первом открытии прилы на новом устройстве:

> **Это новое устройство. Чаты с других твоих устройств сюда не переедут — это особенность шифрования.**
>
> Раньше ты общался с N людьми. Хочешь написать им снова с этого устройства?

Ниже — список аккаунтов (аватар + имя + UIN). Тык на карточку → открывается профиль → стандартная модалка создания чата.

Юзер может закрыть баннер навсегда ("я понял, спасибо"). Список «осиротевших» больше не показывается на этом устройстве.

### Эндпоинт
`GET /api/v1/chat/read-orphan-peers` — подробный контракт в [`api-contracts.md`](api-contracts.md). Отдаёт `[{ account_id, uin, username, last_chat_at }]`. Только для текущей сессии. Возвращает только `account_id`-ы, ни одного метаданного чата (название, история — ничего).

### Приватность
Сервер всегда знал метаданные чатов (название, пара устройств — это в [`server.md`](server.md)). Орфан-список — это просто запрос, который аккаунт делает сам у себя через свою же сессию. Утечки нет.

## Onboarding-модалка при создании первого чата

Показывается **один раз** при создании первого чата на каждом конкретном устройстве (после этого ставим флаг в локальном key-value, больше не показываем):

> **Как работают чаты в Нормисах**
>
> Каждый чат привязан к этому устройству. Если ты зайдёшь со второго устройства — этого чата там не будет.
>
> Чтобы общаться с тем же человеком с другого своего устройства, попроси его создать ещё один чат, выбрав в твоём профиле нужное устройство.
>
> Это особенность сквозного шифрования: приватные ключи каждого чата хранятся только здесь и не передаются между устройствами.
>
> [Понятно]

Без анимаций, без иконок. Просто текст и кнопка.
